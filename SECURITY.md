# Security policy

This project is a static client-side application. It has no accounts, backend or application telemetry. Preferences and calibration are stored locally in the browser. Repository hosting and external reference websites are separate services.

## Supported code

Security fixes target the latest code on `main`. There is currently no commitment to backport fixes to older snapshots.

## Reporting a vulnerability

Please do not publish exploit details in a public issue. If available, use **Security → Advisories → Report a vulnerability** in this repository:

https://github.com/lookee/computational-kitchen/security/advisories/new

Private reporting must be enabled by the maintainer. If it is unavailable, open a public issue containing only a request for a private contact channel, without the vulnerability or sensitive data. No private reporting channel is assumed to be enabled by these files.

Include the affected commit, browser, reproduction steps and impact, using fictitious data. Do not include tokens, personal schedules or unrelated system information. Reports are handled on a best-effort basis; no response-time promise is made.

Scientific model limitations and recipe disagreements belong in ordinary issues unless an actual software vulnerability is involved.
